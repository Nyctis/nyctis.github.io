How Beetle works

Buyers and sellers meet on Solana, then connect directly. The chain handles money. Everything else stays between the two machines.

Money waits on chain

The buyer's payment goes into escrow and the seller locks a bond. The Beetle program pays out on facts it can check.

The chain holds only what it must

Money and commitments go on chain. Addresses and keys go on it only in sealed form.

A job is a short recipe

Say what the model should learn, which base model to use, how long to train and what counts as a pass. The recipe travels sealed, with your data.

{
  "method": "memory",
  "base": "qwen3.5-2b",
  "lora": { "rank": 16, "alpha": 32 },
  "optim": { "lr": 0.002, "epochs": 4 },
  "acceptance": { "min_gain": 0.5 }
}

Jobs run in a sandbox with no network

It measures a baseline, trains, then scores the result on a test the training never saw. The adapter and scores come back sealed.

You set the floor

Evidence decides a seller's tier. Your key goes only to a seller that meets your floor.
